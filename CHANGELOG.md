# Changelog

## Unreleased

- Keep PDF text rendering mode 3 (invisible) as selectable, searchable SVG text with no paint, instead of dropping it. That mode is how a searchable scanned PDF hides its OCR text layer behind the scanned image, and text is the entire point of that layer; converting it to nothing turned a searchable document into one that was not. A Type3 font's glyph program always paints, so mode 3 is the one mode it still cannot approximate and continues to draw nothing there.
- Draw a PDF annotation's own `/AP` appearance stream: a filled-in form field's value and a sticky note's icon live only there, never in the page content stream, so a converter that reads only page content silently dropped them. Map the appearance's `BBox` onto the annotation's `Rect` the way the spec's own algorithm does, and skip Link and Popup annotations along with anything flagged Hidden or NoView, matching how viewers already treat them.
- Warn when a PDF Type0 font uses a CMap encoding other than Identity-H/V, instead of silently mispositioning its text. Character code equals CID only under Identity; a predefined CMap such as `UniJIS-UCS2-H` — the encoding non-embedded standard CJK fonts use — maps code to CID through a table this converter does not resolve, and reusing the code as the CID key against the font's own `/W` widths made Latin runs mixed into CJK text drift apart mid-word.
- Stop trusting an embedded font merely named "Symbol" or "ZapfDingbats" to match a system font of the same name. A word processor's own subsetted dingbat font commonly encodes its bullets at Private Use Area code points that mean nothing outside that specific embedded font, and treating the name as a green light left such bullets as a missing-glyph box everywhere the literal PUA text wasn't backed by that exact font — draw them as vector outlines instead, as already happens for every other embedded font.
- Select embedded TrueType/OpenType glyphs by the PDF's own character code before trying the ToUnicode-decoded Unicode value, whenever the font carries no `/Encoding` (a symbolic simple font, by the spec's own default). A subsetter commonly keys its cmap by sequential code (1, 2, 3, …) rather than true Unicode, so the previous order let a character whose Unicode value happened to fall in that range land on an unrelated glyph — punctuation and spaces most often, since their low codepoints collide with a subset's small code range. A DOCX round-tripped through a common PDF exporter rendered "document-svg / sample document" as "document2vgfVfsampleddocument".

- Let a stencil defer to the colours of the cell it is drawn for. mxStencil's `fill`, `stroke` and `inherit` name the cell's own colours rather than colours of their own, and reading them as literal colours left every stencil that uses them painted solid black — ten of draw.io's own stencil libraries, the network and rack sets among them.
- Draw every remaining shape draw.io implements in code that the example diagrams reach for. The painter grew what they needed: a gradient fill, a stroke colour and a stroke width per part. The shapes are the mock-up window, scroll bar, spinner, checkbox group, column chart, video player, map pin, ratings in stars and hearts, portrait and callout; the integration channels and the network bus; the iOS app tile, action sheet, location bar, striped and map backgrounds and pin; the Android status bar; the Bootstrap image and striped button; the infographic circular callout; the logic gates; the process column and valve; SysML's parameter node and item flow; the lean mapping lead time bar; the smiley faces; and the network icon, which draws the tile and then the stencil the style names on it.
- Convert the shapes draw.io draws as long runs of coordinates from the editor's own code rather than transcribing them, and keep them in `src/drawio/artwork.rs`.
- Across the 613 diagrams in the draw.io project's own example repository, 547 now convert without a single warning, up from 476 when this work started, and nothing is left undrawn except `mxgraph.world`, which ships only with the hosted editor, and the AWS 3D service glyphs, which live in the editor's own code and are named as missing in the warning.

- Convert draw.io (diagrams.net) files. `.drawio`, `.dio` and `.xml` inputs are read as mxGraphModel, one SVG per `<diagram>` page, including the URI-encoded, raw-deflated, base64 body the editor writes by default. - Draw `curvedConnector2` through `curvedConnector5` as curves. They fell through to the bounding-box fallback, which put a stroked rectangle on the slide where a line should curve between two shapes.
- Read `<a:buChar>`, `<a:buNone>`, `marL` and `indent` from a PPTX paragraph's own properties. Bullets were only picked up from a master's text styles, so the usual way a deck writes a bulleted list produced no bullets at all, and the text wrapped against the master's margin rather than the paragraph's.
- Label line, area and scatter chart categories too, under the points rather than at slot centres, and leave the labels off once a chart has more categories than can be read.
- Read `<c:barDir>` and `<c:grouping>` on a bar chart. A horizontal bar chart was drawn as a column chart, and a stacked chart was drawn clustered, which turns a single column of 146 into two columns of 64 and 82.
- Draw the category names on a bar chart. They were already parsed out of the chart part but never reached the page, leaving bars with nothing to identify them.
- Ask for `pixelated` image rendering only where an image is actually drawn larger than its own pixel grid. `/Interpolate false` is about enlargement, but CSS `pixelated` also disables the area averaging every PDF viewer applies when reducing, which speckled scans placed at a fraction of their pixel size.
- Resolve XML entities in Office attribute values. The raw, still-escaped bytes were taken verbatim and escaped again, so an alt text of `R&D` reached the reader as `R&amp;D`. 58 of the 364 Office files in the review corpus carry an entity in a `descr`, `name` or `title`.
- Grow a PPTX table row to fit its wrapped cell text. `<a:tr h="...">` is a minimum height, and treating it as final clipped the second line off every wrapped cell.
- Render a PPTX gradient slide background as a gradient. `<p:bg>` was tracked as one colour, so a two-stop background collapsed to whichever stop was read last and a title slide meant to fade came out flat. 6% of the decks in the review corpus use one.
- Honour `showMasterSp="0"`. A layout that hides the master's shapes was ignored, so anything a template repeats on both — a footer, a logo — was drawn twice. 27 of 259 decks in the corpus set it.
- Undo PNG predictors on Flate images here instead of relying on the PDF library. `/DecodeParms` given as an indirect reference or as an array parallel to `/Filter` was not read at all, and the Average row filter was reconstructed as `left + above / 2` rather than `(left + above) / 2`. Either one turns a predicted image into noise with no warning anywhere; a 15-page deck rendered as static on every page.
- Parse an embedded Type 1 font program once per page instead of once per text-showing operator. `parse_type1` decrypts the eexec section and scans the whole program, and re-running it per operator dominated Type 1-heavy PDFs: a 252-page document went from 168 s to 11 s with byte-identical output.
- Ignore `a14:hiddenFill` / `a14:hiddenLine` compatibility paint on DOCX text boxes. Their black line colour was being read as the shape fill, covering the text with a solid black rectangle.
- Keep DOCX text box paragraphs that overflow the declared frame. Word's default `noAutofit` lets text spill out, so cutting the layout off at the frame height silently dropped every paragraph after the first in a short box.
- Resolve XML entity references in PPTX shape text, PPTX table text, DOCX text and chart labels. quick-xml reports these separately from text, so "R&D" reached the SVG as "RD"; 12.7% of the documents in the review corpus were losing characters this way.
- Emit each image's data URI once, as SVG 2 `href`, instead of repeating it in `xlink:href` for pre-2019 renderers. Image-heavy output shrinks by 40-48%. Renderers older than librsvg 2.46 will no longer show these images.
- Read a PPTX shape's extent as a magnitude, so a shape written with a negative `cx`/`cy` keeps its text instead of being dropped, and say "zero-sized transform" rather than "no explicit transform" when a shape really has one.
- Keep converting a PDF when one image cannot be decoded. An unusable image is now a page warning instead of an error that discards every other page, and the JBIG2 filter is named in that warning rather than relaying the decoder's "missing feature" text.
- Budget a PDF image against the samples it actually expands to instead of assuming RGBA. Ordinary 600 DPI bilevel scans no longer fail the whole document against the "RGBA limit".
- Warn when a PDF page consumes content operators but draws nothing, and say so explicitly when the document was encrypted — a stream left encrypted by a failed per-object decryption previously produced a silently blank page.
- Label an embedded Office image from its byte signature instead of its file name. A JPEG stored as `media/image1.png` was declared `image/png` in the data URI and dropped entirely by strict SVG renderers.
- Materialize a DOCX `PAGE` field that has no `fldCharType="separate"` marker, so footers that Word has never calculated still show a page number.
- Resolve PPTX slide-number fields to the page number instead of emitting PowerPoint's cached `<#>` placeholder text.
- Name the empty slide list or worksheet list when a PPTX or XLSX declares none, instead of reporting "input contains no renderable pages".
- Describe the actual encrypted-PDF behaviour in the README, `SUPPORT.md` and `ARCHITECTURE.md`: a user password is refused, while the empty-user-password form that only carries permission flags is opened, as any viewer opens it.
- Add the `setup-docsvg` and `document-preview` composite actions, plus a reusable `document-preview` workflow that converts the documents a pull request changes and reports page and warning counts.
- Add `.github/copilot-instructions.md` and `copilot-setup-steps.yml` so GitHub Copilot gets the build commands, the conversion accuracy rules and a prepared toolchain.
- Add Claude Code commands `/document-svg:convert`, `/document-svg:reverse`, `/document-svg:preview` and `/document-svg:setup`.
- Resolve the CLI through one shared `ensure-docsvg` script used by the skill wrappers and the GitHub CLI extension, including a release cache and an opt-in checksum-verified release download.

## 0.1.0 — initial source release

- PDF, PPTX, XLSX and DOCX conversion to per-page SVG.
- Node.js in-memory previews, browser display helpers and Python bindings.
- SVG packaging into PPTX, DOCX and XLSX, without reconstructing Office semantics.
- Codex and Claude Code plugins, plus Japanese, English and Simplified Chinese preview guides.
- Bounded preview rendering, external-reference checks and non-overwriting atomic output publication.
- Dual licensing under MIT OR Apache-2.0, with required notice retention under the chosen license.

This is an alpha source release. Prebuilt npm/PyPI distributions and a separate GitHub CLI extension release are not yet published. Visual fidelity and supported format limitations are documented in `docs/SUPPORT.md`.
