能做什么

每个例子都从真实常见的困扰说起，再讲清楚会有什么改变、怎么开始。

🔍在代码审查中直接看到文档改动

审查者看到的是改动后的页面，而不是“二进制文件已更改”。

适合谁
把需求文档、设计资料、报价单放在 Git 仓库里管理的团队。
现在的困扰
PowerPoint、Excel 或 PDF 改了之后，拉取请求里只显示“二进制文件已更改”。想看内容，只能把文件下载下来自己打开。
用了 document-svg 之后
每个改动的文档都会转换成按页的 SVG，可以从工作流运行结果中一次性下载。评论里会列出每个文档的页数和警告数，哪些文件需要仔细看，一眼就知道。
怎么开始
在仓库里添加一个调用附带工作流的简短配置文件即可，本地不需要安装任何东西。

🖥️在自己的应用里预览上传的文件

服务器上不用装 Office，也不用买收费查看器，就能显示文档。

适合谁
需要在内部系统或网络服务中显示用户上传资料的开发者。
现在的困扰
想预览 Office 文件，往往要在服务器上装 Office 或转换软件、购买查看器 SDK，或者把文件发给外部转换服务。
用了 document-svg 之后
从 Node.js 或 Python 调用，就能拿到每页一个 SVG，之后当普通图片显示即可。转换在你的服务器内完成，文件不会外流。
怎么开始
用 npm 或 pip 安装软件包，调用转换函数。如果只需要 PDF、Word、Excel、PowerPoint，还有在浏览器里完成转换的 WebAssembly 版本（需要自己构建）。

🧭让图和代码一起保持最新

每次重新生成文档，图也会从文本重新生成。

适合谁
在设计文档或 Wiki 里放架构图的工程师。
现在的困扰
在别的工具里画好图再贴成图片，代码改了，图却还是旧的，也查不到是谁、什么时候改的。
用了 document-svg 之后
用 draw.io、Mermaid、PlantUML、D2、Graphviz 的文本把图放在代码旁边，每次构建文档时转换成 SVG。图的改动也能像代码一样审查。
怎么开始
在文档构建步骤里加一行转换图的命令。

🛠️没有 CAD 也能检查图纸和模型

在网页上查看图纸、电路板和三维模型。

适合谁
在制造或建筑现场需要审图、但自己不画图的人，以及为他们做内部工具的开发者。
现在的困扰
哪怕只想看一张图纸，也需要昂贵的 CAD 软件和许可证。给每个审图的人都配一套并不现实。
用了 document-svg 之后
平面图（DXF）、电路板（Gerber）、加工路径（G-code）、三维模型（STL、OBJ、STEP）等，都能显示在网页或仪表板上。
怎么开始
先在支持格式列表里查一下你的文件格式能绘制到什么程度。有些格式显示的是内容概要，而不是完整图形。

📊把数据变成报告用的图片

表格、图表和公式，每次生成都一模一样。

适合谁
需要自动生成定期报告或技术资料的人。
现在的困扰
每个人把表格、图表做成图片的方法都不一样，每次生成的效果也略有差别。
用了 document-svg 之后
CSV 表格、图表数据和 LaTeX 公式都能生成每次都一样的 SVG。放大不会模糊，打印也可以直接用。
怎么开始
准备好数据文件，用和其他文档相同的命令转换即可。

🤖让 AI 助手读懂文档

用一个可靠的步骤，代替截图和浏览器自动化。

适合谁
想让 AI 智能体帮忙审阅或制作资料的人。
现在的困扰
要让 AI 看文档，通常得截图或者自动操作浏览器。两种办法都容易出错，也不知道 AI 到底看到了多少。
用了 document-svg 之后
把一个固定流程交给 AI：先把文件转换成页面，再看报告里有没有遗漏。哪里没转换成功，AI 读报告就能自己发现。
怎么开始
安装 Claude Code 或 Codex 的插件，或者直接让 AI 使用命令。

🔁把编辑好的图交回 Office 或 CAD

把 SVG 打包成 PowerPoint、Word、Excel、draw.io 或 CAD 文件。

适合谁
开发生成或编辑 SVG 的工具、需要把结果以 Office 或 CAD 文件交付的开发者。
现在的困扰
收到一堆 SVG 文件，同事没法用平时的软件打开。
用了 document-svg 之后
SVG 可以打包成 PowerPoint、Word、Excel、PDF、draw.io、DXF 文件。转回去的是外观，段落、单元格和公式不会重建。draw.io 的图如果在 SVG 里嵌入了原始图数据，就能以可编辑的状态转回去。
怎么开始
指定 SVG 所在的文件夹，运行写回命令。
