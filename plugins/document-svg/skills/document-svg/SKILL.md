# Document SVG

Use this skill when the requested output is a directory of self-contained SVG pages. The converter selects the parser from the input file and writes `page-NNNN.svg` plus `conversion.json`.

## Convert

DICOM Part 10 images (`.dcm`, `.dicom`) render one PNG-backed SVG page per frame. DICOM Structured Reports (`.sr.dcm`, `.dicom-sr` or SR SOP Class) render bounded Content Sequence tables. Supported compressed transfer syntaxes include JPEG and JPEG 2000 Part 1 lossless/general (`.90`/`.91`) plus RLE Lossless; JPEG 2000 dimensions/components/precision are checked before decoding. DICOMDIR (`DICOMDIR`, `.dicomdir`) follows image-record offsets and resolves File IDs under the DICOMDIR directory. Image previews omit patient/study attributes, but burned-in pixel text remains and is not anonymized; SR previews carry a separate PHI warning.
DICOM Encapsulated PDF Storage is rendered only when its SOP Class and `application/pdf` MIME type agree. The embedded PDF is limited to 64 MiB and uses the bounded PDF engine; DICOM attributes are omitted, but information already inside the PDF remains.

## Transform SVG

1. Resolve the input to an `.svg` file.
2. Choose an output file path (e.g. `<input-stem>.transformed.svg`).
3. Run:

   ```bash
   scripts/transform-document.sh <input.svg> <output.svg> [options]
   ```

   Supported transform options:
   - `--minify`: Strip unnecessary whitespace, comments, and redundant tokens to reduce file size.
   - `--responsive`: Remove fixed width/height and ensure viewBox is set for responsive web scaling.
   - `--monochrome <color>`: Unify all fill and stroke colors to a single monochrome color (e.g. `#000000`).
   - `--precision <digits>`: Clamp coordinate precision to N decimal digits.
   - `--remove-metadata`: Strip `<metadata>`, `<desc>`, and `data-*` attributes.

## Reverse to OOXML, PDF, CAD, CAM, or draw.io

1. Resolve the input to one `.svg` file or a directory containing SVG pages. Directory pages are ordered lexicographically, so prefer `page-NNNN.svg` names.
2. Choose a new output file ending in a supported extension, such as `.pptx`, `.docx`, `.xlsx`, `.pdf`, `.drawio`, CAD/CAM/3D (`.dxf`, `.gcode`, `.gbr`, `.plt`, `.drl`, `.stl`, `.3mf`, `.obj`, `.ply`, `.step`, `.iges`), simulation (`.msh`, `.vtk`), diagrams (`.dot`, `.mmd`), data/math (`.md`, `.csv`, `.tex`), PNG, WebP, standalone HTML viewer (`.html`), React/Vue/Svelte code, SVG path data, or `.datauri`.
3. Run:

   ```bash
   scripts/reverse-document.sh <input.svg-or-directory> <output>
   ```

4. Report the output format and page count, and always disclose that Office outputs embed SVGs as vector images with PNG compatibility fallbacks (PPTX uses one SVG per slide, DOCX one SVG per page, and XLSX one SVG per sheet). CAD/CAM/CAE outputs (`.dxf`, `.gcode`, `.gbr`, `.plt`, `.drl`, `.stl`, `.obj`, `.step`, `.msh`, `.vtk`) generate native vector geometry, 3D meshes, boundary curves, toolpaths, or simulation grids.
5. Do not describe reverse conversion as a lossless restoration of the original Office document. Paragraphs, tables, spreadsheet cells and formulas, charts, comments, masters, and other semantics are not reconstructed.
6. A `.drawio` output is the exception: an SVG that still carries its diagram source is restored as editable shapes. That applies to draw.io's own exports made with "Include a copy of my diagram" and to SVGs this converter wrote with `--embed-drawio-source`. The report says how many pages were restored that way; report that number instead of assuming, because the rest are pictures inside a diagram.

## CLI availability

The repository installer normally places `docsvg` on `PATH`. If it is unavailable, the wrapper can run the checked-out Rust repository when either the current directory is that repository or `DOCUMENT_SVG_REPO` points to it. Otherwise, ask the user to run `./scripts/install-codex-plugin.sh` from the repository root.

## Constraints

- The converter intentionally rejects encrypted PDFs and does not bypass access controls.
- Legacy PowerPoint Binary `.ppt` presentations follow the live `CurrentUserAtom`/`UserEditAtom`/persist-directory chain, then extract UTF-16 or low-byte Unicode text from slide OfficeArt textboxes and outline references into A4 flow pages. Slide geometry, visual styles, images, charts, tables, media, notes, and embedded objects are omitted; encrypted decks are rejected. See `docs/SUPPORT.md` for limits.
- Legacy Word Binary `.doc` documents and CFB `.dot` templates (`.dot` is content-sniffed to preserve Graphviz) extract the main-story text from the bounded FIB/CLX piece table or simple text range. UTF-16 and common compressed code pages are supported. Text is flowed to A4 pages; tables are flattened, and original formatting, pagination, images, headers/footnotes and embedded objects are omitted. Encrypted files are rejected; macros are never executed. See `docs/SUPPORT.md` for limits.
- KiCad PCB `.kicad_pcb` files are parsed as bounded S-expressions. The 2D preview renders common tracks, vias, pads, Edge.Cuts, board/footprint artwork, and cached zone fills; it never evaluates DRC, refills zones, opens 3D/image paths, or loads external libraries. Unsupported custom pads/curves and non-unit affine-scaled footprints are warned and omitted.
- PDF JPXDecode grayscale/RGB/CalGray/CalRGB images with 1–16-bit unsigned, full-resolution components are dimension-checked and decoded to PNG within fixed limits. One embedded alpha channel is preserved when `SMaskInData=1`; DeviceGray/DeviceRGB/CalGray/CalRGB preblended mode 2 is unblended using a valid `/Matte`, and bounded DeviceGray external `/SMask` images are applied when no matte or nested mask is present. Default/0 ignores embedded alpha. Explicit `/Mask`, unsupported matte or soft-mask color spaces, unsupported JPX color spaces, and subsampling remain as JPEG 2000 data with a warning; PDF-level masks may be lost from the SVG fallback. `BitsPerComponent` is taken from the codestream as required by PDF.
- OpenDocument Text previews preserve headings, paragraphs, lists, and tables, and embed bounded package-linked PNG/JPEG images as centered flow blocks. Legacy OpenOffice XML packages (`.sxw`, `.stw`, `.sxg`) are routed through the same bounded ODT engine after validating their `application/vnd.sun.xml.*` mimetype. Styles and exact pagination are not reconstructed; image anchors and wrapping are approximated, and external or inline-binary images are reported and omitted.
- EPUB previews follow the OPF spine and embed bounded package-linked PNG/JPEG XHTML `img` resources. Remote references, CSS backgrounds, SVG and other image sources are not fetched or reconstructed.
- DocBook 4/5 `.dbk`/`.docbook` previews render bounded titles, sections, paragraphs, lists, source blocks, simple tables, and validated local PNG/JPEG `imagedata`/`graphic` resources. DTDs, XInclude, external links, MathML, scripts, and publisher extensions remain inert.
- Standalone HTML previews embed bounded relative PNG/JPEG `img src` files only when canonical paths remain inside the input directory tree. Image placement, CSS sizing and wrapping are approximated; external and escaping paths are not fetched.
- Markdown previews embed bounded local PNG/JPEG resources from standalone or paragraph `![alt](path)` references when resolved paths remain inside the input directory tree; images render as flow blocks, while heading/list/quote/table/code images stay as alt text.
- OpenDocument Spreadsheet previews preserve cached cell values and embed bounded package-linked PNG/JPEG images after each sheet table; legacy OpenOffice XML packages (`.sxc`, `.stc`) use the same safe package checks. Cell anchoring, chart/vector drawings, styles, and formula recalculation are not reproduced.
- OpenDocument Presentation/Drawing previews preserve page order, size, common vector shapes, editable text, and bounded PNG/JPEG images linked from the ODF package. Legacy OpenOffice XML presentations/drawings (`.sxi`, `.sti`, `.sxd`, `.std`) are accepted through the same engines. External and inline binary images plus charts, tables, OLE, and advanced effects are omitted or approximated with warnings; see `docs/SUPPORT.md` for limits.
- Visio Open XML (`.vsdx`/`.vsdm`/`.vstx`/`.vstm`) and legacy VDX XML use bounded page/ShapeSheet rendering; legacy Visio CFB (`.vsd`/`.vss`/`.vst`/`.vsw`) is summarized as inert stream metadata without decoding opaque drawing payloads.
- ZIP-backed Apple iWork Pages/Numbers/Keynote packages (`.pages`/`.numbers`/`.key`) expose bounded package marker metadata only; IWA protobuf, formulas, media, previews, scripts and external links remain inert. `.key` is distinguished from LS-DYNA by ZIP signature.
- Autodesk DWG (`.dwg`) reads only the six-byte AC10xx version header and file size; compressed sections, entities, macros, embedded objects and external references remain inert.
- Nastran Output2 (`.op2`) performs bounded record-framing and table-label preflight only; model/result payloads, external paths and solver operations remain inert.
- IPC-2581 (`.ipc2581`/`.ipc-2581`/`.cvg`) summarizes PCB Content/BOM/ECAD/AVL structure and manufacturing counts without rendering coordinates, toolpaths, attachments or executing operations.
- Siemens JT (`.jt`) reads only the fixed Version header and byte-order marker; TOC/LSG, tessellation, Parasolid geometry, PMI and external resources remain inert.
- Rhino/OpenNURBS 3DM (`.3dm`) reads only the stable start marker and bounded header bytes; NURBS/mesh chunks, plug-ins, textures and external resources remain inert.
- Microsoft Access ACE/Jet (`.accdb`/`.accde`/`.mdb`/`.mde` and related extensions) reads only the first-page engine marker and bounded metadata; database objects, VBA/data macros, attachments, encryption and linked paths remain inert.
- Dassault 3DXML (`.3dxml`) validates the local Manifest→Root relationship and bounded product-structure XML; binary 3DRep tessellation, external files, textures and viewer automation remain inert.
- HDF5 scientific containers (`.h5`/`.hdf5`/`.hdf`/`.h5part`) and CGNS/HDF5 CFD files (`.cgns`) are preflighted from their signature and superblock without loading datasets, links, filters, or solver payloads.
- RTF previews preserve supported ANSI codepages, Unicode escapes, paragraphs, explicit `\page` breaks, bounded embedded PNG/JPEG pictures, and declared picture goal dimensions. Anchors/cropping/wrapping are approximated; EMF/WMF pictures, objects, and unsupported media are omitted with warnings.
- XPS/OpenXPS (`.xps`/`.oxps`) and Autodesk DWFx (`.dwfx`) follow internal fixed-document relationships and render basic Path/Glyphs content plus embedded PNG/JPEG ImageBrushes clipped to Path bounds. Embedded fonts, exact glyph advances, gradients/cropping and resource dictionaries are warned or approximated; classic DWF payloads and external resources are never fetched.
- TIFF/BigTIFF (`.tif`/`.tiff`) emits one SVG per image directory and embeds a decoded PNG. Unsigned-integer grayscale (including packed 1/2/4-bit samples), RGB/RGBA, and CMYK are supported; WhiteIsZero/BlackIsZero is honored and channels above 8-bit are reduced to 8-bit. Palette, signed/floating-point samples, and ICC profiles are not interpreted. Per-page and total pixel/data limits and `max_pages` apply.
- DICOM Part 10 (`.dcm`, `.dicom`) emits one SVG per image frame and applies available Modality/VOI transformations. Patient/study metadata is omitted, but burned-in annotations remain; the preview is not de-identification. Only grayscale/RGB 8/16-bit pixels and supported transfer syntaxes are decoded; JPEG 2000 Part 1 `.90`/`.91` frame dimensions, component count, precision, signedness and subsampling are checked against DICOM attributes before decode. JPEG-LS, JPEG 2000 YBR_RCT/YBR_ICT color conversion, Part 2, HTJ2K, orientation and physical pixel spacing are not handled.
- DICOMDIR (`DICOMDIR`, `.dicomdir`) follows root/next/lower-level Directory Record offsets and renders referenced `IMAGE` records in hierarchy order. File IDs are validated and canonicalized inside the DICOMDIR folder, and duplicate/missing/unsupported references are skipped with warnings.
- DICOM Encapsulated PDF Storage (`1.2.840.10008.5.1.4.1.1.104.1`) accepts only `application/pdf`, checks the optional declared length and padding, and renders the bounded embedded stream with the PDF engine. DICOM attributes are not copied, but PDF content can still identify a patient, so the preview is not de-identification.
- FDF form data (`.fdf`; content sniffing) uses the PDF object/xref grammar to render fully-qualified field hierarchy, types, safe values, password masking, choice options and action/attachment counts. JavaScript, submit/launch actions, file specifications, embedded files and external URLs remain inert or redacted; no form submission or PDF page rendering runs. Limits are 64 MiB input, 500,000 objects, depth 64, 100,000 fields, 2 MiB/value and 32 MiB total values. Source: [Adobe FDF reference](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.2.pdf).
- XFDF XML form data (`.xfdf`, `.xfdf.xml`; content sniffing) renders bounded fully-qualified field/value hierarchy, sensitive-field masking, rich-text and annotation counts, and PDF target/ID counts. PDF references, actions, JavaScript, rich-text payloads, appearance data and external URLs remain inert or redacted; no form submission, annotation import or PDF rendering runs. Limits are 64 MiB input, 1,000,000 XML events, 500,000 nodes, depth 96, 100,000 fields and 100,000 rows. Source: [ISO 19444-1 XFDF](https://www.iso.org/standard/74272.html).
- DICOM Structured Reports (SR) render Basic Text, Enhanced, Comprehensive, Comprehensive 3D, Extensible, CAD, dose, agent and related SOP Classes as bounded Content Sequence rows for TEXT/NUM/CODE/CONTAINER items, concepts, units and relationships. Referenced images/audio/waveforms, UIDs and patient/study attributes are omitted; SR content may contain PHI and is not de-identification. Limits are 128 MiB input, 1,000,000 structural tokens, 100,000 elements, depth 64 and 200,000 rows. Source: [DICOM PS3.3 Structured Report IODs](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_A.35.html).
- Microsoft Project XML (`.xml` with the Microsoft Project namespace, or `.mspdi`) renders bounded task Gantt pages with supplied dates, progress, milestones, and simple predecessor arrows. It rejects DTDs, does not fetch links or external entities, and does not recalculate work calendars or schedules; see `docs/SUPPORT.md` for limits.
- PCL PCD (`.pcd`) accepts ASCII, little-endian binary, and LZF-compressed point clouds. Bounded XYZ point marks preserve packed or separate RGB colors, quantized only above 512 color groups. Other fields and non-default VIEWPOINT poses are not applied.
- XYZ ASCII (`.xyz`) accepts common named coordinate/intensity/RGB/normal columns or homogeneous 3/4/6/7/9/10-field layouts with whitespace/comma separators. Intensity is scaled across the observed range; units, CRS and sensor pose are not inferred. Black RGB is retained and normals are omitted.
- ASTM E57 (`.e57`) reads CRC-protected XML and point-data pages, applies per-scan poses, converts spherical coordinates, and preserves normalized RGB or intensity. It caps decoding at 20 million points and previews at 200,000 points. Scan images, CRS reprojection, and non-coordinate attributes are omitted.
- Leica PTS (`.pts`) reads bounded unstructured XYZ/intensity or XYZ/intensity/RGB records; legacy signed integer and normalized decimal intensity are mapped to grayscale, and Leica's reserved no-color RGB uses a blue fallback. The origin is valid; one deterministically sampled page is capped at 200,000 points.
- Leica PTX (`.ptx`) reads structured multi-scan grids, applies the per-scan registration transform and preserves RGB, or displays intensity-only scans in grayscale. Missing XYZ cells and sensor/grid metadata are omitted; deterministic sampling is capped at 200,000 points total.
- Legacy Excel (`.xls`, `.xlt`, `.xla`) renders cached cell values in bounded worksheet pages after validating BIFF dimensions, cell coordinates, and shared-string expansion. Hidden sheets are included with a warning. Formula recalculation, styling, merged-cell geometry, charts, and drawings are omitted; macros are never executed.
- SYLK `.slk` parses bounded `ID`/`B`/`C`/`F`/`E` records into paginated inert tables. Cell coordinates and cached values are retained; formulas, formatting, and other metadata are never evaluated.
- DIF `.dif` parses bounded TABLE/VECTORS/TUPLES/DATA headers and BOT/EOD tuples into inert paginated tables. Numeric, string, boolean, NA and ERROR values are displayed without formula evaluation.
- FASTA/FASTQ sequence files render bounded identifier, length, GC/ambiguity and sequence/quality summaries. FASTQ sequence and quality lengths are checked; no alignment or Phred conversion is performed.
- GFF3/GTF `.gff`/`.gff3`/`.gtf` renders validated nine-column feature annotations and attributes. Directives and embedded FASTA tails are omitted; no hierarchy or sequence analysis executes.
- BED `.bed` and bedGraph `.bedgraph`/`.bg` validate zero-based half-open intervals, optional BED12 blocks and finite signal values as inert tables. Track/browser directives and remote lookups are never loaded.
- VCF `.vcf` renders validated fixed variant columns plus inert FORMAT/sample fields. Metadata/reference URLs and embedded FASTA are omitted; vCard `.vcf` is selected when the VCF signature is absent.
- SAM `.sam` renders validated 11-field alignments and optional tags as inert tables. Header metadata and reference URLs are ignored; no CIGAR projection, genotype analysis, or external resource access occurs.
- WIG/Wiggle `.wig`/`.wiggle` expands fixedStep and variableStep signal declarations into bounded one-based closed interval tables. Track/browser and remote references are ignored.
- MAF `.maf` renders bounded `a`/`s` multiple-alignment blocks with coordinate and ungapped-size validation. Optional metadata, reference lookup and coordinate liftover remain inert.
- Newick `.nwk`/`.newick`/`.tree` renders the first bounded semicolon-terminated phylogenetic tree as a directed graph. Quoted labels, finite branch lengths and nested comments are validated; extra trees, taxonomy/sequence lookup, rooting and distance calculations remain inert.
- Stockholm `.sto`/`.stockholm` renders bounded Stockholm 1.0 alignment blocks, including split sequence rows. `#=GF`/`#=GS`/`#=GC`/`#=GR` annotations remain inert and external profile/sequence lookups are never performed.
- CLUSTAL `.aln`/`.clustal`/`.clustalw` renders bounded block alignments; sequence fragments are concatenated, residue counts and consensus rows remain inert, and external lookup or alignment execution is never performed.
- NEXUS `.nex`/`.nexus` extracts the first bounded `TREE`/`UTREE` statement from `BEGIN TREES` and renders it through the Newick graph path. TAXA/TRANSLATE metadata and additional blocks remain inert.
