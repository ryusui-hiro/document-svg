# Font parser migration and conversion efficiency

2026-09-08 follow-up to the initial alpha source release.

## Changes

- Replaced `ttf-parser` with `skrifa 0.44.0`, the maintained alternative identified by RustSec advisory RUSTSEC-2026-0192. The renderer already uses this version, so the migration removes one dependency without introducing another version of the font stack.
- Kept PDF-specified advances, unhinted font-unit outlines, character-code cmap fallback and raw Type1/CFF fallback. Malformed outline errors now propagate to the existing warning/fallback path instead of being ignored.
- Added synthetic-font regressions for TrueType contours, quadratic curves, composites, spaces, missing glyphs, malformed glyphs, OpenType CFF and `.notdef` handling. Added a public PDF conversion test for embedded TrueType outlining and deterministic output. No third-party font files are included.
- Reused the font database within each reverse conversion instead of rescanning system fonts per page. Each new conversion still loads its own database; there is no global stale-font cache.
- Kept the existing serialized IR-size metric while counting bytes without retaining a page-sized JSON allocation.
- Borrowed text/attributes when XML escaping is unnecessary, avoiding repeated copies of embedded image data. Escaping and control-character behavior remain unchanged.
- Excluded native shared-library build products (`.so`, `.pyd`, `.dylib`) from Git and flagged them in publication checks if explicitly staged.

## Measured comparison

Baseline: commit `e9500a2`, release-mode CLI. Local macOS arm64 measurement; one warm-up followed by three interleaved runs per binary. Values below are medians. Fixtures are generated by `scripts/benchmark-conversion.py`.

| Workload | Before | After |
|---|---:|---:|
| 100 small SVG pages containing text → PPTX, elapsed | 0.9785 s | 0.1037 s |
| DOCX containing a synthetic 2048×2048 PNG → SVG, elapsed | 0.1197 s | 0.0707 s |
| Same DOCX, peak resident memory | 136.19 MiB | 50.61 MiB |

The benchmark verified byte-identical PPTX packages and SVG output across all runs. The reported IR size remained exactly 22,374,739 bytes. These are targeted synthetic workloads, not general speed guarantees for every document.

```sh
python3 scripts/benchmark-conversion.py --before /path/to/baseline/docsvg --after target/release/docsvg
```

The script needs Python 3.10+, macOS or Linux, and `/usr/bin/time`. It creates its own fixtures and removes its temporary directory afterward. Font-outline command sequences can differ between parsers while representing the same contour; the byte-equality benchmark applies to the two workloads above, not to every outlined PDF.

## Verification

The migrated lockfile contains no `ttf-parser`, and the RustSec audit reports no vulnerabilities or maintenance warnings. Workspace tests, formatting and Clippy cover the implementation; the language bindings are rebuilt against the new core. The initial-release audit remains historical evidence for v0.1.0 rather than the current dependency state.
